### 1️⃣ 氣泡排序法 (Bubble Sort)

#### 📝 演算法概述
氣泡排序是最簡單的排序演算法之一。它的名稱來自於算法的工作方式：較小的元素會逐漸"浮"到列表的頂部，而較大的元素則會沉到底部，就像氣泡一樣。

#### 🔄 算法原理
1. **比較相鄰元素**：從陣列的開始，比較相鄰的兩個元素
2. **交換順序**：如果第一個元素大於第二個元素，則交換它們的位置
3. **重複掃描**：對陣列中的每一對相鄰元素重複上述過程
4. **完成一輪**：經過一輪完整掃描後，最大的元素會移動到陣列末尾
5. **忽略已排序部分**：在下一輪中，忽略已經排序好的部分，重複步驟1-4
6. **直到排序完成**：當陣列完全排序或不需要再進行交換時，算法結束

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n) | 陣列已排序，僅需一次掃描 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 陣列反向排序，需要最多比較 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 🎯 算法簡單易懂，邏輯清晰
- 🛡️ 穩定排序，不改變相等元素的相對位置
- 💾 原地排序，節省空間
- 🔍 實現簡單，適合教學

#### ❌ 缺點
- 🐢 效率較低，適合小規模數據
- 📈 時間複雜度為O(n²)，不適合大規模排序
- 🔄 比較和交換次數較多

#### 🎯 適用場景
- 📚 教學演示和學習算法基礎
- 📊 小規模數據集（n < 100）
- 🎓 編程初學者練習
- ✍️ 需要穩定排序的場景

#### 💻 代碼實現（JavaScript）
```javascript
function bubbleSort(arr) {
    const n = arr.length;
    for (let i = 0; i < n - 1; i++) {
        for (let j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                // 交換
                [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
            }
        }
    }
    return arr;
}
```

### 2️⃣ 插入排序法 (Insertion Sort)

#### 📝 演算法概述
插入排序的工作方式類似於整理撲克牌。我們逐次從未排序的部分取出一個元素，並將其插入到已排序部分的正確位置。

#### 🔄 算法原理
1. **初始狀態**：將陣列的第一個元素視為已排序部分
2. **選擇元素**：從第二個元素開始，逐次選取未排序部分的第一個元素
3. **向後比較**：將選中的元素與已排序部分的元素進行比較，從右向左
4. **後移元素**：如果已排序元素大於選中元素，則該元素向右移動一位
5. **插入位置**：重複比較直到找到正確位置或到達陣列開頭
6. **插入元素**：在找到的位置插入選中的元素
7. **重複過程**：重複步驟2-6，直到所有元素排序完成

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n) | 陣列已排序，每個元素只需一次比較 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 陣列反向排序，需要最多比較和移動 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 🎯 直觀易懂，適合日常理解
- 🛡️ 穩定排序，保持相等元素的相對位置
- 💾 原地排序，空間效率高
- ⚡ 對於部分有序陣列效率較高
- 🎮 適應性好，可根據數據特點調整

#### ❌ 缺點
- 📈 平均時間複雜度為O(n²)，效率不夠高
- 🔄 移動操作較多，尤其是在數組開頭
- 🐢 對大規模數據集性能一般

#### 🎯 適用場景
- 📚 小到中等規模數據排序（n < 1000）
- 📊 部分有序的數據集
- 🎓 教學和學習排序算法
- 💼 實時數據流排序
- 🎮 遊戲分數排序等簡單應用

#### 💻 代碼實現（JavaScript）
```javascript
function insertionSort(arr) {
    for (let i = 1; i < arr.length; i++) {
        const key = arr[i];
        let j = i - 1;
        
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
    return arr;
}
```

### 3️⃣ 選擇排序法 (Selection Sort)

#### 📝 演算法概述
選擇排序通過在未排序部分中重複查找最小元素，並將其放置在已排序部分的末尾来實現排序。

#### 🔄 算法原理
1. **初始化**：將整個陣列視為未排序部分
2. **查找最小值**：在未排序部分中查找最小元素的索引
3. **交換位置**：將最小元素與未排序部分的第一個元素交換
4. **縮小範圍**：已排序部分擴大一個元素，未排序部分縮小一個元素
5. **重複過程**：重複步驟2-4，直到整個陣列排序完成
6. **完成排序**：當未排序部分只剩一個元素時，排序完成

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n²) | 即使陣列已排序，仍需進行所有比較 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 需要進行最多的比較操作 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 🎯 算法簡單直觀，易於理解
- 💾 原地排序，空間效率高
- 📉 交換次數較少（最多n-1次交換）
- 🛡️ 穩定性可通過修改算法實現
- 🎮 適合需要最小化交換操作的場景

#### ❌ 缺點
- 📈 時間複雜度始終為O(n²)，效率固定較低
- 🔍 比較次數較多，不如冒泡排序靈活
- 🌀 不穩定排序（基礎版本）
- 🐢 不適合大規模數據集

#### 🎯 適用場景
- 📚 教學演示和學習排序基礎
- 💰 內存交換操作成本較高的系統
- 📊 小規模數據排序（n < 100）
- 🎓 編程初學者練習
- 🎮 簡單應用中對交換次數有要求的場景

#### 💻 代碼實現（JavaScript）
```javascript
function selectionSort(arr) {
    for (let i = 0; i < arr.length - 1; i++) {
        let minIndex = i;
        
        // 查找最小元素
        for (let j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }
        
        // 交換最小元素到正確位置
        [arr[i], arr[minIndex]] = [arr[minIndex], arr[i]];
    }
    return arr;
}
```

### 4️⃣ 合併排序法 (Merge Sort)

#### 📝 演算法概述
合併排序是一種基於分治策略的高效排序演算法。它將大問題遞迴地分解為較小的子問題，分別解決後再將結果合併。這種方法保證了穩定且高效的性能。

#### 🔄 算法原理
1. **分割陣列**：將陣列從中點分為左右兩個子陣列
2. **遞迴排序左部分**：對左子陣列遞迴執行合併排序
3. **遞迴排序右部分**：對右子陣列遞迴執行合併排序
4. **基本情況**：當子陣列只有一個元素時，停止遞迴
5. **比較合併**：將已排序的左右子陣列進行合併
6. **選擇較小值**：每次比較兩個子陣列的首元素，選出較小的加入結果
7. **處理剩餘**：將一個子陣列已用完後，將另一個子陣列的剩餘元素全部加入
8. **返回結果**：得到一個完全排序的陣列

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n log n) | 任何情況下都需要進行分割和合併 |
| 平均情況 | O(n log n) | 穩定的效能表現 |
| 最壞情況 | O(n log n) | 性能保證，不隨數據變化 |
| 空間複雜度 | O(n) | 合併過程需要額外的暫存空間 |

#### ✅ 優點
- ⚡ 性能穩定，最壞情況也是O(n log n)
- 🛡️ 穩定排序，保持相等元素的相對位置
- 🎯 分治思想清晰易於理解
- 📊 適合大規模數據集排序
- 🔄 適合外部排序和並行處理

#### ❌ 缺點
- 💾 需要O(n)的額外空間進行合併操作
- 📈 空間複雜度較高，在記憶體受限環境中不理想
- 🐢 小規模數據上可能不如簡單排序算法快
- 🔍 實現相對複雜，包含遞迴和合併邏輯

#### 🎯 適用場景
- 📚 大規模數據排序（n > 10000）
- 🎓 需要穩定排序的場景
- 💼 外部排序和文件排序
- 🖥️ 多重排序或並行處理
- 🎮 實時系統中性能有保證的需求

#### 💻 代碼實現（JavaScript）
```javascript
function mergeSort(arr) {
    if (arr.length <= 1) return arr;
    
    // 分割
    const mid = Math.floor(arr.length / 2);
    const left = mergeSort(arr.slice(0, mid));
    const right = mergeSort(arr.slice(mid));
    
    // 合併
    return merge(left, right);
}

function merge(left, right) {
    const result = [];
    let i = 0, j = 0;
    
    while (i < left.length && j < right.length) {
        if (left[i] <= right[j]) {
            result.push(left[i++]);
        } else {
            result.push(right[j++]);
        }
    }
    
    return result.concat(left.slice(i)).concat(right.slice(j));
}
```

## 💡 相關提示

### 何時使用各種排序算法
| 情況 | 推薦算法 | 原因 |
|------|---------|------|
| 小規模數據 | 冒泡/插入/選擇 | 實現簡單，開銷小 |
| 部分有序 | 插入排序 | 適應性強，效率高 |
| 交換代價大 | 選擇排序 | 交換次數少 |
| 大規模數據 | 快速排序/歸併排序 | 平均O(n log n)複雜度 |
| 需要穩定性 | 歸併排序/插入排序 | 保持相對位置 |
| 高效能保證 | 歸併排序 | O(n log n)複雜度保證 |
