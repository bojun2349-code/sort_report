<summary><strong>氣泡排序法</strong></summary>

#### 📝 演算法概述
氣泡排序是最簡單的排序演算法之一。它的名稱來自於算法的工作方式：較小的元素會逐漸浮到列表的頂部，而較大的元素則會沉到底部，就像氣泡一樣。

#### 🔄 算法原理
1. **比較相鄰元素**：從陣列的開始，比較相鄰的兩個元素
2. **交換順序**：如果第一個元素大於第二個元素，則交換它們的位置
3. **重複掃描**：對陣列中的每一對相鄰元素重複上述過程
4. **完成一輪**：經過一輪完整掃描後，最大的元素會移動到陣列末尾
5. **忽略已排序部分**：在下一輪中，忽略已經排序好的部分，重複步驟1-4
6. **直到排序完成**：當陣列完全排序或不需要再進行交換時，算法結束

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n) | 陣列已排序，僅需一次掃描 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 陣列反向排序，需要最多比較 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 算法簡單易懂，邏輯清晰
- 穩定排序，不改變相等元素的相對位置
- 原地排序，節省空間
- 實現簡單，適合教學

#### ❌ 缺點
- 效率較低，適合小規模數據
- 時間複雜度為 O(n²)，不適合大規模排序
- 比較和交換次數較多

#### 🎯 適用場景
- 教學演示和學習算法基礎
- 小規模數據集（n < 100）
- 編程初學者練習
- 需要穩定排序的場景

#### 💻 代碼實現（JavaScript）
```javascript
function bubbleSort(arr) {
    const n = arr.length;
    for (let i = 0; i < n - 1; i++) {
        for (let j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
            }
        }
    }
    return arr;
}
```

<summary><strong>插入排序法</strong></summary>

#### 📝 演算法概述
插入排序的工作方式類似於整理撲克牌。我們逐次從未排序的部分取出一個元素，並將其插入到已排序部分的正確位置。

#### 🔄 算法原理
1. **初始狀態**：將陣列的第一個元素視為已排序部分
2. **選擇元素**：從第二個元素開始，逐次選取未排序部分的第一個元素
3. **向後比較**：將選中的元素與已排序部分的元素進行比較，從右向左
4. **後移元素**：如果已排序元素大於選中元素，則該元素向右移動一位
5. **插入位置**：重複比較直到找到正確位置或到達陣列開頭
6. **插入元素**：在找到的位置插入選中的元素
7. **重複過程**：重複步驟2-6，直到所有元素排序完成

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n) | 陣列已排序，每個元素只需一次比較 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 陣列反向排序，需要最多比較和移動 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 直觀易懂，適合日常理解
- 穩定排序，保持相等元素的相對位置
- 原地排序，空間效率高
- 對於部分有序陣列效率較高
- 適應性好，可根據數據特點調整

#### ❌ 缺點
- 平均時間複雜度為 O(n²)，效率不夠高
- 移動操作較多，尤其是在數組開頭
- 對大規模數據集性能一般

#### 🎯 適用場景
- 小到中等規模數據排序（n < 1000）
- 部分有序的數據集
- 教學和學習排序算法
- 實時數據流排序
- 遊戲分數排序等簡單應用

#### 💻 代碼實現（JavaScript）
```javascript
function insertionSort(arr) {
    for (let i = 1; i < arr.length; i++) {
        const key = arr[i];
        let j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
    return arr;
}
```

<summary><strong>選擇排序法</strong></summary>

#### 📝 演算法概述
選擇排序通過在未排序部分中重複查找最小元素，並將其放置在已排序部分的末尾來實現排序。

#### 🔄 算法原理
1. **初始化**：將整個陣列視為未排序部分
2. **查找最小值**：在未排序部分中查找最小元素的索引
3. **交換位置**：將最小元素與未排序部分的第一個元素交換
4. **縮小範圍**：已排序部分擴大一個元素，未排序部分縮小一個元素
5. **重複過程**：重複步驟2-4，直到整個陣列排序完成
6. **完成排序**：當未排序部分只剩一個元素時，排序完成

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n²) | 即使陣列已排序，仍需進行所有比較 |
| 平均情況 | O(n²) | 隨機排列的陣列 |
| 最壞情況 | O(n²) | 需要進行最多的比較操作 |
| 空間複雜度 | O(1) | 原地排序，僅需常數額外空間 |

#### ✅ 優點
- 算法簡單直觀，易於理解
- 原地排序，空間效率高
- 交換次數較少（最多 n-1 次交換）
- 穩定性可通過修改算法實現
- 適合需要最小化交換操作的場景

#### ❌ 缺點
- 時間複雜度始終為 O(n²)，效率固定較低
- 比較次數較多，不如冒泡排序靈活
- 不穩定排序（基礎版本）
- 不適合大規模數據集

#### 🎯 適用場景
- 教學演示和學習排序基礎
- 交換代價高的系統
- 小規模數據排序（n < 100）
- 編程初學者練習
- 簡單應用中對交換次數有要求的場景

#### 💻 代碼實現（JavaScript）
```javascript
function selectionSort(arr) {
    for (let i = 0; i < arr.length - 1; i++) {
        let minIndex = i;
        for (let j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }
        [arr[i], arr[minIndex]] = [arr[minIndex], arr[i]];
    }
    return arr;
}
```

<summary><strong>合併排序法</strong></summary>

#### 📝 演算法概述
合併排序是一種基於分治策略的高效排序演算法。它將大問題遞迴地分解為較小的子問題，分別解決後再將結果合併。這種方法保證了穩定且高效的性能。

#### 🔄 算法原理
1. **分割陣列**：將陣列從中點分為左右兩個子陣列
2. **遞迴排序左部分**：對左子陣列遞迴執行合併排序
3. **遞迴排序右部分**：對右子陣列遞迴執行合併排序
4. **基本情況**：當子陣列只有一個元素時，停止遞迴
5. **比較合併**：將已排序的左右子陣列進行合併
6. **選擇較小值**：每次比較兩個子陣列的首元素，選出較小的加入結果
7. **處理剩餘**：將一個子陣列已用完後，將另一個子陣列的剩餘元素全部加入
8. **返回結果**：得到一個完全排序的陣列

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n log n) | 任何情況下都需要進行分割和合併 |
| 平均情況 | O(n log n) | 穩定的效能表現 |
| 最壞情況 | O(n log n) | 性能保證，不隨數據變化 |
| 空間複雜度 | O(n) | 合併過程需要額外的暫存空間 |

#### ✅ 優點
- 性能穩定，最壞情況也是 O(n log n)
- 穩定排序，保持相等元素的相對位置
- 分治思想清晰易於理解
- 適合大規模數據集排序
- 適合外部排序和並行處理

#### ❌ 缺點
- 需要 O(n) 的額外空間進行合併操作
- 空間複雜度較高，在記憶體受限環境中不理想
- 小規模數據上可能不如簡單排序算法快
- 實現相對複雜，包含遞迴和合併邏輯

#### 🎯 適用場景
- 大規模數據排序（n > 10000）
- 需要穩定排序的場景
- 外部排序和文件排序
- 多重排序或並行處理
- 實時系統中需要性能保證的需求

#### 💻 代碼實現（JavaScript）
```javascript
function mergeSort(arr) {
    if (arr.length <= 1) return arr;
    const mid = Math.floor(arr.length / 2);
    const left = mergeSort(arr.slice(0, mid));
    const right = mergeSort(arr.slice(mid));
    return merge(left, right);
}

function merge(left, right) {
    const result = [];
    let i = 0, j = 0;
    while (i < left.length && j < right.length) {
        if (left[i] <= right[j]) {
            result.push(left[i++]);
        } else {
            result.push(right[j++]);
        }
    }
    return result.concat(left.slice(i)).concat(right.slice(j));
}
```

<summary><strong>雙調排序法</strong></summary>

#### 📝 演算法概述
雙調排序法是一種利用雙調序列（bitonic sequence）進行排序的演算法。它先將資料分成一段遞增和一段遞減，再透過多次比較與交換，最終合併成完整排序結果。

#### 🔄 算法原理
1. **建立雙調序列**：將陣列分割成兩部分，一部分升冪、一部分降冪
2. **遞迴排序**：對兩部分分別遞迴執行雙調排序
3. **雙調合併**：將雙調序列按照指定方向進行合併
4. **回傳結果**：遞迴直到子序列長度為 1，最終得到完整排序陣列

#### ⏱️ 時間複雜度分析
| 情景 | 時間複雜度 | 說明 |
|------|-----------|------|
| 最好情況 | O(n log² n) | 演算法比較次數固定，與輸入順序無關 |
| 平均情況 | O(n log² n) | 遞迴合併需要多層比較 |
| 最壞情況 | O(n log² n) | 固定深度的比較模式 |
| 空間複雜度 | O(log² n) | 遞迴消耗額外堆疊空間 |

#### ✅ 優點
- 規則化比較模式，適合平行硬體實現
- 在比較網路與並行排序中有教學價值
- 遞迴結構適合規劃固定步驟的排序流程

#### ❌ 缺點
- 不是最適合一般串列排序的演算法
- 空間與時間成本高於部分 O(n log n) 演算法
- 基本版本非穩定排序

#### 🎯 適用場景
- 平行處理或硬體加速的排序
- 需要規則比較流程的教學與演算法設計
- 資料長度為 2 的冪次（或接近）時更容易實現

#### 💻 代碼實現（JavaScript）
```javascript
function bitonicSort(arr, low = 0, cnt = arr.length, dir = 1) {
    if (cnt <= 1) return;
    const k = Math.floor(cnt / 2);
    bitonicSort(arr, low, k, 1);
    bitonicSort(arr, low + k, cnt - k, 0);
    bitonicMerge(arr, low, cnt, dir);
}

function bitonicMerge(arr, low, cnt, dir) {
    if (cnt <= 1) return;
    const k = Math.floor(cnt / 2);
    for (let i = low; i < low + k; i++) {
        if ((dir === 1 && arr[i] > arr[i + k]) || (dir === 0 && arr[i] < arr[i + k])) {
            [arr[i], arr[i + k]] = [arr[i + k], arr[i]];
        }
    }
    bitonicMerge(arr, low, k, dir);
    bitonicMerge(arr, low + k, k, dir);
}
```

寫報告最難的地方，是要把演算法講得對、講得清楚，還要讓頁面看起來不亂。為了做到這點，我先把每個算法的流程一步一步拆開，然後把重點寫成簡單易懂的句子，最後再回頭檢查整體的排版和內容是不是一致。

雙調排序最讓我卡住，因為它比較抽象，很多人看了也不一定懂什麼是雙調序列。後來我把它想成「先讓一半升冪、一半降冪，再慢慢把它合在一起」，這樣講起來比較有畫面。
